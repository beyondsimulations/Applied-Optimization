# Review: lecture-12-rail.qmd

**Reviewed:** 2026-07-07
**Scope:** Pedagogy, model formulation, math notation, content robustness, writing polish

## Summary

A strong case-study lecture: the real-world Qatar 2022 framing is compelling, the question-driven build-up of the unusual set $\mathcal{R}_{e,t}$ is handled carefully, and the results/impact section (heuristic, Shanghai scaling, honest discussion of the "disappearing passengers" simplification) closes the loop in a way many lectures skip. The main weaknesses are notational: the letter `d` is used simultaneously as a destination index and as the travel-time parameter (including `d_{o,d}`, where the symbol collides with its own subscript), the spreading-ratio slide shadows a free index with a summation index, and the model never declares the domain of $X_{o,p}$. Several numeric claims in the results section contradict each other.

## 1. High-impact teaching improvements

- **Surface what the objective actually does** (line ~430). Since $q_{o,d,p}$ is a parameter, $\sum_{o,p}(\sum_d q_{o,d,p} - m X_{o,p})$ is a constant minus $m\sum_{o,p} X_{o,p}$ — "minimizing queues" is exactly "maximizing total admitted passengers". This equivalence is a genuine aha moment (and explains why the model has no queue dynamics), but it is never stated. Add a fragment after the objective: "Question: What does the solver *really* maximize here?"
- **Hidden infeasibility trap** (lines ~590 and ~624). Combining $X_{o,p} \geq c_o^{min}$ with $\sum_d q_{o,d,p} - m X_{o,p} \geq 0$ makes the model **infeasible whenever a station's queue is smaller than $m \cdot c_o^{min}$** (e.g., a quiet station late at night with $c_o^{min}=2$, $m=15$, and 20 people queued: $30 > 20$). This is a classic modeling pitfall worth a discussion slide — how would students fix it? ($c_o^{min}=0$, or $m \times X_{o,p} \geq \min(m\, c_o^{min}, \sum_d q_{o,d,p})$, or soft constraints.) The "Model Assumptions" slide (line ~667) asks about queues but not about this.
- **Reconcile the α<1 constraint with the 109% result** (lines ~314, ~555, ~719). The capacity constraint enforces utilization ≤ α·100% with α strictly below 1, yet "Key Results" reports maximum utilization drops "from 316% to 109%". An attentive student will ask how a hard constraint can be violated. Explain that the 109% arises in the rolling-horizon heuristic/simulation with realized (not forecast) demand — one sentence on the Key Results slide resolves it.
- **Add a learning-objectives slide.** The lecture jumps from the title into the World Cup story; a short "After today you will be able to… (model time-expanded flows with precomputed delays, translate a safety goal into inflow control, embed an LP in a rolling-horizon heuristic)" would frame the unusually complex set machinery.

## 2. Model & notation issues

- **Symbol collision on `d`** (lines ~309–311, ~344–345): `d` is the destination index ($o,d \in \mathcal{O}$), but `$d_e$`, `$d_{o,d}$`, and `$d_{o,e}$` use `d` as the travel-time parameter. `$d_{o,d}$` literally uses the same letter as name and subscript. Rename travel times to `$\tau$` (e.g., $\tau_e$, $\tau_{o,e}$).
- **Index shadowing in the spreading ratio** (line ~361): $\frac{q_{o,d,p}}{\sum_{d \in \mathcal{O}} q_{o,d,p}}$ uses `d` as both the free index (numerator) and the bound summation index (denominator) — as written the ratio is ill-defined. The constraint slide (line ~555) correctly switches the denominator index to `f`; do the same here for consistency.
- **Variable domain never declared:** the full model (lines ~644–652) has no $X_{o,p} \geq 0$ / continuity statement. Non-negativity is only implied via $c_o^{min} \leq X_{o,p}$ (and only if $c_o^{min} \geq 0$, which is never stated). The "Model Characteristics" slide asks students about domains — fine — but the final model box should still state $X_{o,p} \in \mathbb{R}_{\geq 0}$ (and whether fractional people per minute are acceptable).
- **Garbled set-builder for $\mathcal{R}_{e,t}$** (lines ~480–490): the first line "$(o,d) | o,d \in \mathcal{O}$" mixes an element pattern with a vertical bar inside the conditions; the closing brace sits inside the `array` environment before `p \in \mathcal{P}`, so the rendered set closes in the wrong place. Clean version: $\mathcal{R}_{e,t} = \{(o,d,p) : o,d \in \mathcal{O},\ p \in \mathcal{P},\ q_{o,d,p} > 0,\ e \in \mathcal{C}_{o,d},\ t - d_{o,e} \in I_p\}$.
- **"period $t$" should be "minute $t$"** (line ~498): the explanation of $\mathcal{R}_{e,t}$ says "capacity utilization of arc $e$ in period $t$", but $t \in \mathcal{T}$ indexes minutes; periods are $p$. Same slip in the parameter list at line ~543 ("in time $t$" is fine, but keep the minute/period distinction sharp — it is the entire point of the two time sets).
- **Example tuple format mismatch** (line ~509): $\mathcal{R}_{e,t}$ is defined over triples $(o,d,p)$, but the example lists $\{((A,D),3), \dots\}$ — nested pairs. Write $(A,D,3)$ etc. (Internal check: with $m=2$, element $(C,D,11)$ requires $d_{C,(C,D)} = 0$, giving $t - 0 = 22 \in I_{11} = \{21,22\}$ ✓; the other elements imply $d_{A,(C,D)} \in \{16,17\}$, $d_{B,(C,D)} \in \{12,13\}$, $d_{E,(C,D)} \in \{4,5\}$ — the figure's travel times are path-rendered in the SVG so I could not verify them, but the slide should state them so students can check.)
- **α misapplied to stations** (lines ~314, ~579, ~590): $\alpha$ is defined as "maximal allowed *arc* utilization", yet the inflow bound uses $\alpha \times c_o^{max}$ on a *station* entry rate. Either broaden the definition ("safety factor applied to all capacities") or introduce a separate station factor.
- **Unused parameters:** $d_e$ (line ~310) and $d_{o,d}$ (line ~344) never appear in the model — $d_e$ only feeds the shortest-path computation and $d_{o,d}$ is never used at all. Either drop $d_{o,d}$ or say explicitly that $d_e$ is input to Dijkstra and $d_{o,e}$ is what the model consumes.
- **$q$ described inconsistently:** "Demand from station $o$ to $d$" (line ~309) vs. "People queued to travel" (lines ~418, ~541, ~612). Demand-per-period and standing queue are different things (the heuristic later transfers "remaining queues" between periods); pick "queued passengers" everywhere.

## 3. Content & robustness

- **Contradictory performance numbers:** "~1.4 seconds per planning period" (line ~721), "Yes (~1-65s)" in the comparison table (line ~772), and "< 2 minutes per period" for Shanghai (line ~734). If 1–65 s covers all instances, Shanghai cannot need up to 2 minutes; align the three claims.
- **Comparison table undercuts itself** (line ~773): "Network Scale — Other Methods: up to 327 stations; Our Approach: **302+ stations**". 302 < 327, so the bolded row reads as a *loss*, and the "+" is unexplained. Either state the actual claim (e.g., comparable scale at far lower runtime) or drop the row.
- **"11× larger" check** (line ~731): Shanghai 302 stations is ~8× the Doha Metro (37 stations), not 11×. If 11× refers to the modeled subnetwork (~27 nodes), say so; as written the number does not follow from anything on the slides.
- **Two Unsplash background URLs** (lines ~13, ~680) are fragile external dependencies — same image loaded twice from Unsplash's CDN. Move to the course image host like `ao_metro-crowd.png`.
- **Two different image hosts:** `images.beyondsimulations.com` (line ~30) vs `images.byndsim.com` (lines ~174, ~197). Consolidate to one domain to halve the failure modes.
- **Filename/title mismatch:** file is `lecture-12-rail.qmd` but the title and all content say "Metro". Minor, but the footer link text "Home" pointing at `lecture-12-rail.qmd` (line ~7) perpetuates it; consider at least aligning the title convention with other lectures.
- **No references:** the lecture is built on a real project and claims "State-of-the-Art" (line ~779) and a comparison with "Other Methods", but the Literature section (line ~807) only links the general Julia reading list. Cite the underlying paper(s) — students should be able to check the 25,941→4 and Shanghai numbers.
