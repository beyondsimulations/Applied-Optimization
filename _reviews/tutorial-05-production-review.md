# Review: tutorial-05-production.qmd

**Reviewed:** 2026-07-07
**Scope:** Pedagogy, model formulation, math notation, code, content robustness, writing polish

## Summary

A well-scaffolded tutorial: giving the tricky inventory-balance constraint away for free while leaving the easier constraints to the student is exactly the right difficulty gradient, and the provided plotting/cost functions plus assert-based validation cells are genuinely good practice. The main weaknesses are silent correctness traps: the variable hint never mentions domains (`Bin`, `>= 0`) and the validation doesn't check them (without `W ≥ 0` the model is unbounded), and the capacity-constraint prose omits setup-time consumption, so a student can build a wrong model that still passes every assert.

## 1. High-impact teaching improvements

- **Close the variable-domain trap.** The tip (line ~194) shows `@variable(model, x[keys(dictBottlingTime), keys(dictAvailableTime)])` with no domains, and the text never says to add `Bin` or `>= 0`. The validation (lines ~227–229) checks binary/continuous type but **not lower bounds**. A student who declares `WarehouseStockPeriodEnd` without `>= 0` gets an *unbounded* model: with `Y = X = 0`, the balance constraints let `W_{i,1}` (which appears in no constraint of the base model except the t=2 balance) cascade arbitrarily negative through all periods, driving the objective to −∞. Either extend the tip ("don't forget `Bin` for `productBottled` and `>= 0` for the other two") or add `@assert all(v -> has_lower_bound(v) && lower_bound(v) == 0, productQuantity)` (and the same for `WarehouseStockPeriodEnd`) to the validation cell.
- **Surface the week_05 capacity crunch.** The data has a built-in "aha": week_05 offers only 48 h of capacity while its own demand alone requires ~102 h of pure bottling time (I computed this from `demand.csv` × `bottlingtime.csv`; all other weeks need 70–110 h of 168 h). Pre-production and inventory build-up are therefore *forced*, which is the whole point of the CLSP — yet the tutorial never mentions it. A one-line question ("Look at `availabletime.csv`: what happens around week_05, and what do you expect in the warehouse plot?") would connect the data to the model and give Task 4 ("is the workload distributed evenly?") a concrete anchor.
- **Explain what Task 1's model actually gets wrong.** The base model has no balance constraint for the first period, so week_01 demand is simply never enforced and `W_{i,1}` acts as *free initial inventory conjured from nothing* (at 0.1 €/bottle holding cost). Task 2 fixes this, but the text only says "the solution space is smaller" (line ~536). Say explicitly: "In Task 1 the model could invent starting stock and ignore week-1 demand — check your Task-1 production plot: nothing is bottled in week_01." That turns the fix into an insight about model debugging.
- **Task 4 asks for a schedule the model no longer contains.** Section 4 (line ~601) says "Analyze the production schedule outlined in section 2", but by then the student has cumulatively added the section-3 maintenance constraints and re-solved — the current variable values reflect section 3, not section 2. Either move Section 4 before Section 3, or tell students to re-run sections 1–2 (skipping 3) first, or change the reference to "section 3".
- **Add validation cells for the two student-built constraints.** The setup constraint (line ~309) and capacity constraint (line ~317) have no asserts at all — errors only surface via the very wide final objective range (539,900–700,000), which a capacity constraint *without* setup time would likely still pass. A simple `num_constraints(lotsizeModel, AffExpr, MOI.LessThan{Float64})` count check would catch missing constraint families.

## 2. Model & notation issues

- **Capacity-constraint description omits setup time** (line ~314): "limits the production quantity to the number of bottles that can be bottled within the available time" describes only `b_i·X_{i,t} ≤ a_t`, but the lecture model (lecture-05-production.qmd, line ~342) is `Σ_i (b_i·X_{i,t} + g_i·Y_{i,t}) ≤ a_t` — setup time also consumes plant time. Reword to "...limits the total bottling time **plus setup time** per period to the available time."
- **Setup-constraint prose is backwards** (line ~306): "ensure that we setup the production for a beer type only if we bottle the type at least once" states `Y = 1 ⟹ X > 0`, which is *not* what the big-M constraint `X_{i,t} ≤ M·Y_{i,t}` enforces (that direction is left to optimality). Say: "ensure that a beer type can only be bottled in a period if production is set up for it in that period." Also consider naming it as the big-M constraint from the lecture so students make the connection.
- **Task 2 instruction is ambiguous** (line ~520): "incorporate an initial stock for all types of beer of zero at the beginning of the initial planning period." The intended fix is the *missing first-period balance* `X_{i,1} − W_{i,1} = d_{i,1}` (initial stock 0), but a student can plausibly read it as `WarehouseStockPeriodEnd[i, first_period] == 0` — which constrains *end-of-period* stock and still ignores week-1 demand. Spell out: "add the inventory balance for the first period, assuming zero stock before it." (The unused `first_period` scaffolding at line ~290 hints at this but is never referenced again.)
- **Three inconsistent bounds for the Task-1 objective:** the assert uses `539900 <= … <= 700000` (line ~337), its message says "between 539,000 and 700,000" (line ~337), and the prose says "range of 600,000 to 700,000" (line ~340). Pick one story; if 539,900 is a solver-variability cushion, say so.
- **Fragile claim** (line ~340): "If your model is solved within seconds, your formulation is not correct." Solve time depends on hardware and HiGHS version; with the tight per-beer big-M (`Σ_τ d_{i,τ}`) this 162-binary model may well solve near-optimally within seconds on a fast machine, wrongly telling a correct student they failed. Prefer a check on the reported *bounds/gap* or drop the sentence.
- **`objective_value` can error under the time limit:** with `set_time_limit_sec(…, 60.0)` (line ~182), a slow machine may hit the limit with no incumbent, in which case the validation cells (lines ~337, ~533, ~574) throw a JuMP error instead of a helpful assert message. Guard with `primal_status(lotsizeModel) == FEASIBLE_POINT`.
- **Weak assert logic** (line ~228): `@assert all(is_integer, productQuantity) == false` only requires that *not all* variables are integer; `!any(is_integer, productQuantity)` matches the intent (same for line ~229). Also worth one sentence on *why* bottle quantities are modeled continuous although bottles are discrete (numbers are large, LP relaxation error is negligible) — currently the choice is silently imposed.

## 3. Content & robustness

- **The worked examples use keys that don't exist in the data** (lines ~131 and ~203): `("IPA", "week_1")` — the data has no beer "IPA" (types are Pilsener, Blonde_Ale, Amber_Ale, Brown_Ale, Porter, Stout) and periods are zero-padded (`week_01`, not `week_1`). A student who tests `dictDemand["IPA","week_1"]` or `x["IPA", "week_1"]` gets a `KeyError`. Use a real key, e.g. `("Pilsener", "week_01")`.
- **Package management is inconsistent with the course setup:** a hidden cell runs `Pkg.add` for six packages at render time (lines ~30–41) although the project uses `Project.toml` + `activate_environment.qmd`; `CSV` is used (line ~47) but appears neither in that `Pkg.add` block nor in the callout tip (line ~57); `DelimitedFiles` is added and loaded but never used; and a *visible* `import Pkg; Pkg.add("PlotlyKaleido")` sits mid-`using` block (line ~52), running a network install on every render. Clean this to a single hidden environment cell (or rely on the activate include) and fix the tip's package list.
- **First validation cell is invisible** (lines ~115–124): it uses `#| echo: false`, unlike all later validation cells which use `#| code-fold: true`. Students reading the rendered page cannot see what is being checked on the parameters. Make it code-fold for consistency.
- **String-sorting of periods silently relies on zero-padding** (lines ~284, ~290–291): `sort` on `week_01 … week_27` happens to be chronological only because of the two-digit padding. One sentence in the callout ("this works because the periods are zero-padded") would prevent nasty surprises when students reuse the pattern.
- **Typo in an assert message** (line ~533): "between 659,9000 and 760,000" → "659,900".
- The `code-links` entry `tutorial-05-production.jl` (line ~7) does not exist in the repo but is generated by the post-render `convert_pypercent.py` pipeline — fine, no action needed.

## 4. Pedagogy & polish

- **Naming inconsistency in required variable names** (line ~189): `productBottled` and `productQuantity` are lowerCamelCase, `WarehouseStockPeriodEnd` is UpperCamelCase. Since students must type these exactly (asserts check the names), pick one convention, e.g. `warehouseStock`.
- **No learning objectives:** a two-line opener ("After this tutorial you can implement a CLSP in JuMP, handle string-indexed periods, and diagnose an incomplete model") would frame the session, matching the style recommended for the lectures.
- **Grammar/wording:** "we setup the production" → "we set up production" (line ~306); "Note, that `#=` and `=#` are a comment delimiter" → "Note that … are comment delimiters" (line ~603); "implemented inside of a function" → "inside a function" (line ~349); "Please name them `productBottled` for the binary variable" — say what the binary *means* (setup indicator) at first mention (line ~189).
- **"Biannual" is ambiguous** (line ~624): it can mean twice a year or every two years. Given the 27-week horizon, presumably "semiannual (every six months)" is meant — say that.
- **Redundant code fragments:** `value(productBottled[i,t])>0.5 ? true : false` → just the comparison (line ~372); `productionResults = create_production_results()` is recomputed before every plot even back-to-back (lines ~433, ~441, ~540, ~546); `ceil(Int, …)` on inventory (line ~374) can overstate stock by up to one bottle — `round(Int, …)` is truer to the solution.
- **Cost breakdown uses raw binary values** (line ~464): `value(productBottled[i,t])` from a MIP incumbent can be 0.9999…; multiplying it into the setup cost gives slightly off numbers in the cost plot. Use `round(value(…))`.
- **Section 5 duplication** (lines ~630–632): "Your answer goes here." immediately followed by a "YOUR ANSWER BELOW" comment cell — drop the stray sentence.
